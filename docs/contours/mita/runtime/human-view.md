# Просмотр сессии человеком (аварийный доступ)

> docs-as-state: этот документ описывает то, что есть сейчас, по исходникам репозитория
> `cloud-tech-tasks` (`infra/web-browser/view.sh`) и по конфигурации узла вне этого
> репозитория (`/var/lib/infra/src`, роли `kiosk_browser` и `nginx`); снимок на
> 2026-08-08/09, дата чтения — 2026-08-10. Устройство браузерного стека целиком —
> `docs/runtime/browser.md`, здесь только контур просмотра. Кто вправе выдать ссылку и
> когда — вопрос политики, сегодня этого решает MITA сама (PACT не существует); целевое
> разнесение описано в `docs/spec/spec.md` §11, здесь только указатель, без пересказа.

## 1. Назначение

Контур нужен для эскалации, когда автоматизация упирается в то, что должен пройти
человек: капча, ручной вход, MFA-код с телефона (см. `docs/playbooks.md`,
`captcha-escalation`). Он поднимает на короткое время удалённый экран конкретного
браузерного инстанса (`docs/runtime/browser.md` §3) и отдаёт на него одноразовую
ссылку. Вне сеанса просмотра контур ничего не слушает наружу.

## 2. Обёртка `infra/web-browser/view.sh`

Файл `infra/web-browser/view.sh` в `cloud-tech-tasks` — тонкая обёртка (29 строк, из
них 24 — комментарии; исполняемого кода — 4 строки) над системной командой
`/usr/local/sbin/kiosk-browser-session`, которая разворачивается ролью Ansible
`kiosk_browser` из `/var/lib/infra/src`. Вызов идёт через `sudo`:

```bash
#!/usr/bin/env bash
set -euo pipefail
[ $# -eq 0 ] && set -- status
exec sudo /usr/local/sbin/kiosk-browser-session "$@"
```

Команды:

```bash
infra/web-browser/view.sh start <инстанс>   # печатает одноразовую ссылку на экран этого инстанса
infra/web-browser/view.sh stop  <инстанс>   # гасит сразу, ссылка перестаёт работать
infra/web-browser/view.sh stop  --all       # гасит все сеансы разом (в т.ч. чужие!)
infra/web-browser/view.sh status            # что сейчас работает, по всем инстансам
```

Без аргументов — `status`. У `start`/`stop` **имя инстанса обязательно, умолчания
нет**: до исправления 2026-08-08 форма `"${1:-status}"` молча отбрасывала второй
аргумент, и `start larina` доходил до системной команды как просто `start`. Список
доступных имён инстансов — не в этом файле, см. `docs/runtime/browser.md` §3
(источник правды — `/var/lib/infra/src/config/ansible-vars.yml` и `view.sh status`).

Пример вывода `status`:

```
instance         cdp   vnc  view  browser   wayvnc    view-web  cdp-sock     idle  link
default         9222  5900  6080  active    inactive  inactive  active         59  нет
larina          9223  5901  6081  active    inactive  inactive  active         59  нет

nginx                    active
kiosk-browser-idle.timer active
```

## 3. Сетевой путь и защита

Наружу смотрит **один порт и один vhost**: `https://vds.khudoley.pro:22325/<одноразовый
путь>/`. Инстансы различаются только одноразовым путём, не портом. Стек за vhost'ом
(из `docs/runtime/browser.md` §2):

```
телефон → nginx :22325 (TLS)
              ↓ 127.0.0.1:(6080+i)   websockify + noVNC   ← поднимается на сеанс просмотра
              ↓ 127.0.0.1:(5900+i)   wayvnc (без аутентификации, только петля 127.0.0.1)
```

`5900+i` (VNC) и `6080+i` (websockify) слушают исключительно `127.0.0.1` — снаружи к
ним пути в обход nginx нет.

**Аутентификации нет ни на VNC, ни в nginx** — сознательное решение 2026-08-04 (см. §6).
Защита строится целиком на одноразовости пути:

- путь — 96 бит случайности, перебор неосуществим;
- путь живёт один сеанс: снимается по команде `stop`, по жёсткому пределу через
  `timeout(1)` в `ExecStart` юнита просмотра (значение `kiosk_browser_view_max_seconds`,
  сегодня 30 минут; код возврата 124 объявлен успешным через `SuccessExitStatus`, а не
  `RuntimeMaxSec` — шаблон роли отдельно поясняет, почему `RuntimeMaxSec` отвергнут: он
  переводит юнит в `failed` независимо от кода возврата) или при падении процесса
  просмотра (`ExecStopPost` юнита); отдельно закрыт случай перезагрузки узла с ещё активным
  путём — правило `/etc/tmpfiles.d/kiosk-browser-session.conf` снимает путь ещё раз на
  загрузке, до старта nginx (`ExecStopPost` перезагрузку не переживает, это отдельно
  обнаруженный и закрытый дефект);
- vhost логирует запросы без строки пути — сама ссылка не оседает в журналах nginx;
- через 30 минут путь бесполезен по таймауту независимо от того, вызывали ли `stop`.

`systemctl reload nginx` асинхронен: ссылка становится рабочей или нерабочей не
мгновенно, а через секунду-другую после `start`/`stop` — проверка `curl` сразу после
команды может дать 404 на живом сеансе.

Каждому активному инстансу просмотра — свой файл конфигурации
`/etc/nginx/session/kiosk-browser-view/<инстанс>.conf`; несколько сеансов просмотра
**разных инстансов** могут жить одновременно, не мешая друг другу. `stop --all` гасит
все сеансы разом, включая чужие, — этим командам пользоваться с осторожностью на узле
с несколькими одновременными пользователями.

### Остаточный риск

**Внутри 30-минутного окна владение ссылкой равно полному доступу к браузеру этого
инстанса** — второго рубежа защиты нет. Это принятый, а не случайный компромисс
(пользователь явно выбрал удобство против дополнительного фактора при переходе на
одноразовые ссылки, см. §6). Разделение по инстансам этот риск не убирает, а сужает:
утечка ссылки отдаёт злоумышленнику браузер одного владельца, а не всех сразу
(`docs/runtime/browser.md` §5 — тот же принцип и то же ограничение изоляции по
инстансам).

## 4. Место в веб-контуре узла

| Порт | Кто | Что |
|---|---|---|
| 80 | nginx | ACME HTTP-01, остальное 301 → 443 |
| 443 | nginx → apache `127.0.0.1:8008` | заглушка сайта |
| 8080 | никто | зарезервирован под будущее приложение (webapp, этап 3 по ROADMAP.md MITA) |
| 22325 | nginx | контур просмотра браузера (kiosk-browser) |
| 5900+i, 6080+i, 9222+i, 9600+i | роль `kiosk_browser` | только `127.0.0.1` |

TLS — Let's Encrypt на домене `vds.khudoley.pro`, автопродление. HTTP-01 обслуживается
в `default_server`-заглушке nginx на порту 80, а не в самом vhost'е контура просмотра —
у сайта на нестандартном порту 22325 своего `server{}` на 80 намеренно нет; иначе
выпуск и продление сертификата для этого домена были бы невозможны.

## 5. Управление ролью узла (кто и как накатывает)

Контур целиком настраивается вне репозитория `cloud-tech-tasks`, ролями Ansible из
`/var/lib/infra/src`: `kiosk_browser` (юниты просмотра, экраны, VNC) и `nginx`
(vhost `:22325`, `session_include`). В `cloud-tech-tasks` — только документация и
`view.sh`; `/etc/nginx`, `/etc/systemd/system` и профили браузеров руками не правят —
ближайший прогон роли перезапишет правку незаметно.

Прогон — точечный, только этой роли:

```bash
cd /var/lib/infra/src && sudo .venv/bin/ansible-playbook playbooks/optional.yml \
  -e '{"optional_roles_enabled":["kiosk_browser"]}' -e infra_single_role=true
```

`infra_single_role=true` обязателен: без него предполёт `playbooks/preflight/role-list.yml`
требует полного списка зависимостей роли (`claude`, `nginx`) и падает на assert.
Готовая обёртка — `make role ROLE=kiosk_browser`.

**`make optional` и `make site` прогонять нельзя**: оба рестартуют
`claude-remote-control` и рвут живые сессии агентов (в том числе ту, из которой
запущен прогон); `make site` вдобавок трогает `security_hardening`/`nftables`. Прогон
роли `kiosk_browser` идемпотентен (`changed=0` при повторном запуске, проверено дважды).

## 6. Как решение дошло до сегодняшнего вида

Коротко, потому что это уже принятые факты, а не проект:

1. **2026-07-30.** Вопрос удалённого просмотра браузера впервые поднят и сознательно
   отложен пользователем — узел терминальный, живой просмотр потребовал бы
   Xvfb/VNC + открытого порта наружу, а это вопрос безопасности, решать который рано.
2. **2026-07-31.** Построен первый аварийный GUI («контур капчи»): weston + Xwayland +
   noVNC + websockify + Caddy, доступ **публично за TLS и паролем**. SSH-туннель или
   Tailscale/WireGuard зафиксированы как «будущий шаг», но так и не сделаны.
3. **2026-08-04, три итерации подряд.** nginx + certbot вместо Caddy; раскладка портов
   (80/443 — общий веб, 22325 — VNC, 8080 — резерв под приложение); затем по прямой
   просьбе пользователя, работавшего с телефона, — **отказ от обеих пар логин-пароль**
   (basic-auth nginx и VNC-пароль) в пользу одноразового пути с TTL 30 минут.
   VNC-пароль убрать без замены сервера было нельзя (пароль принадлежал weston, у
   которого нет выключателя аутентификации; альтернативы вроде Apple ARD через noVNC
   не подошли) — поэтому заодно заменили `weston` на `cage + wayvnc`, который умеет
   работать вообще без аутентификации.

Итог этой эволюции: решение **не пошло по пути приватного канала (SSH-туннель,
VPN)**, а пошло по пути **публичного vhost на выделенном порту с одноразовым путём**
как единственным рубежом защиты. Это осознанный, явно проговорённый компромисс
удобства и безопасности, а не промежуточное или временное состояние — на 2026-08-09
план вернуться к туннелю не зафиксирован нигде.

## 7. Не реализовано / открытые вопросы

- **Политика выдачи ссылки** (кто вправе инициировать `start`, кому её можно
  показывать, обязана ли она куда-то логироваться) сегодня не существует как
  отдельный механизм — решение принимает сам исполнитель MITA в моменте. Целевое
  разнесение (решение «поднимать ли сеанс» — за PACT) — `docs/spec/spec.md` §11,
  здесь только указатель.
- Второго рубежа защиты внутри окна действия ссылки нет (см. остаточный риск, §3) —
  это принятое состояние, а не забытая задача.
- Разнесение браузерных инстансов по разным системным пользователям (закрытие границы
  «скомпрометированный процесс браузера») не реализовано — см.
  `docs/runtime/browser.md` §5.
