# Волны наращивают объём, а не устройство; этап 0 отклонён

- **Статус:** Принято
- **Дата:** 2026-08-11
- **Контур:** lina
- **Отношение к предыдущим решениям:** отменяет `docs/adr/0014` («Этап 0: Telegram минимальным контуром»)
  целиком. `docs/adr/0015` (Telegram подключается через LINA) сохраняется и усиливается.

## Контекст

`second-system/DECISIONS.md` D-011 предлагал начать с одного экземпляра шлюза, настроенного
конфигурацией, без брокера и собственного кода, с обоснованием «рост идёт добавлением, а не
переписыванием». По таблице `STAGE-0.md` §2 контур LINA был при этом представлен «канальным слоем
шлюза», а границы существовали «в конфигурации, но не в развёртывании».

Для LINA это означало промежуточную форму сразу по трём линиям. Первая: приём сообщения и исполнение
находятся в одном процессе, то есть контур недоверенного ввода и привилегированный контур не разделены
— главное свойство архитектуры отсутствует. Вторая: реплики пользователя попадают к исполнителю без
события «кандидат в задачу», без `reply_route_id` и без проверки полноты, поэтому контракт §13
появляется позже и переучивает уже сложившийся способ работы. Третья: ответ уходит человеку напрямую,
минуя egress-проверку, — то есть строится путь доставки, который затем демонтируется.

## Решение

Принят принцип D-013: **волна ограничивает объём, а не устройство.** Первая волна LINA содержит один
канал, но в целевом виде:

1. Канальный адаптер — отдельная единица развёртывания с собственной учётной записью на брокере;
   публикует сырое входящее, кандидата в задачу, требование уточнения и результат доставки, принимает
   только одобренный результат от egress-части PACT.
2. `reply_route` создаётся доверенным компонентом с первого дня; текст пользователя не является
   источником значений для полей адресации, маршрутизации и полномочий.
3. Состояние диалога живёт в собственной схеме PostgreSQL, состояние доставки ведётся отдельно от
   состояния задачи.
4. Критерий полноты, цикл уточнений с потолками и идемпотентность в обе стороны реализуются сразу:
   ни одно из этих свойств нельзя добавить позже, не переписав способ приёма.

Минимальность выражается объёмом: **один канал, один владелец, один диалоговый сценарий**. Второй
и третий каналы приходят на W3 как новые адаптеры, а не как переделка первого.

`docs/adr/0014` отменяется: его предмет — представление LINA на этапе 0 — перестал существовать вместе
с решением D-011.

## Последствия

**Положительные**

- Инварианты `L-2` (нет пути мимо PACT), `L-4` (результат только после egress-проверки) и `L-5`
  (текст не меняет маршрут) действуют с первого дня, а не появляются на второй волне.
- Негативные тесты §5.3 применимы с первой волны: их не нужно откладывать до появления разделения.
- Контракт §13 не переучивается: пользователь с самого начала взаимодействует с той системой, которая
  останется.

**Отрицательные / что становится дороже**

- Первая волна дороже: адаптер, схема состояния, контракты событий и потолки уточнений появляются
  сразу, тогда как «канальный слой шлюза» настраивался конфигурацией за часы.
- Сроки первой демонстрации отодвигаются: диалог с человеком станет возможен только после того, как
  собран весь сквозной путь, включая enforcement и egress-проверку.
- Цель «получить фактические данные, а не построить систему целиком» (`STAGE-0 §1`) достигается
  медленнее и обеспечивается узостью объёма, а не упрощением устройства.

## Рассмотренные альтернативы

- **Сохранить этап 0 и переучить позже.** Отклонена: переучивание касается не кода, а привычек человека,
  который уже привык ставить задачи в чат без полноты и получать ответ без проверки.
- **Собрать LINA в целевом виде, но без разделения на единицы развёртывания.** Отклонена: граница между
  контурами доверия — не деталь развёртывания, а предмет архитектуры; в одном процессе она выражается
  только дисциплиной кода.
- **Начать не с Telegram, а с веб-чата собственной разработки.** Не отклонена и не выбрана: вопрос
  состава каналов первой версии (`O-8`) остаётся открытым и решается отдельно.

## Условия пересмотра

- Отмена или изменение D-013 на уровне системы.
- Обнаружение, что целевое устройство первой волны недостижимо в разумный срок; в этом случае
  пересматривается **объём** волны (например, до одного сценария без уточнений), а не устройство.
