## Правило этого раздела

Страницы `docs/` (кроме `docs/spec/` и `docs/adr/`) описывают **только то, что
есть сегодня**. Они не имеют права ссылаться на `docs/spec/spec.md` за данными о
поведении системы — исключение сделано только для принципиально неизменных
вещей (расшифровка имени контура, его место в общей схеме контуров). Если
какого-то механизма сегодня не существует, страница обязана прямо написать
«не реализовано» или «не существует», а не пересказывать спецификацию будущим
временем; вопрос при этом закрывается указателем на соответствующий раздел
спецификации, без пересказа его содержания.

Источник правил документооборота: `/tmp/vds-kz-pipeline/research/allocation.md`
§6.

## Спецификация

`docs/spec/spec.md` — единственный файл спецификации участка,
**желаемое (целевое) состояние** контура LINA. Спецификация имеет право
описывать то, чего сегодня не существует, и опережает воркспейс: пользователь
правит спецификацию, а затем просит подогнать под неё воркспейс, а не наоборот.
Статус документа заявлен в его собственной шапке: `spec-as-source`, Draft 0.1,
дата 2026-08-09.

Спецификация обязана ссылаться на источник каждого заимствованного положения
(`CONTOURS.md §N`, `SPECIFICATION.md §N`, `D-00N`, `REVIEW-FINDINGS.md §N`,
`STAGE-0.md §N`, `ROADMAP.md`); положения без ссылки на источник помечены в ней
как «предложение» настоящего документа. Собственный раздел спецификации §25
собирает все открытые вопросы контура — это единственное разрешённое место за
данными о нерешённых вопросах: docs-as-state страницы фиксируют только текущий
факт (что есть и чего нет сегодня) и не собирают открытые вопросы о целевом
устройстве контура.
