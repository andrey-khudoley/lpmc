# Перечень первых интеграций CITA не определён
- **Статус:** Отложено
- **Дата:** не установлена
- **Контур:** cita

## Контекст

CONTOURS.md §13 «Открытые вопросы» прямо перечисляет «перечень исходных
интеграций CITA и целевых систем MITA» в числе семи пунктов, не решённых в
этом документе и подлежащих решению при проработке контуров. Ни в
`second-system/DECISIONS.md` (D-001…D-012), ни в переписке, зафиксированной
там же, выбор не сделан: из двенадцати решений ни одно не называет ни
конкретный сервис, ни конкретную интеграцию как первую для CITA.

Материала для выбора при этом не ноль. `allocation.md` §2.6 прямо говорит:
«сегодня в системе не выполняется ни одной задачи по опубликованному
контракту; вся автоматизация — браузерная», но перечисляет то немногое, что
есть, и обязывает CITA сказать это честно в `docs/`. ADR 0003 (разрез
MITA/CITA по наличию контракта) называет `services/gc-chatium-gateway/`
«ближайшим реальным кандидатом», а ADR 0007 разбирает и отклоняет два других
наблюдённых случая (Kinescope, Bizon365) как не удовлетворяющие критерию
«пригодный опубликованный контракт» на 2026-08-09. Ни один из этих ADR не
назначает интеграцию первой — оба явно оставляют CONTOURS.md §13 открытым.

Известные кандидаты и их фактический статус на 2026-08-09:

- **`services/gc-chatium-gateway/`** — собственный gateway-продукт автора,
  интеграция Chatium↔GetCourse через старый и новый API GetCourse
  (`cloud-tech-tasks/services/gc-chatium-gateway/overview.md`). Раздел
  «Доступ» — TODO: «доступы намеренно не перенесены в этом проходе — решение
  по способу их хранения принимается отдельно». Раздел «Возможности» тоже
  неполный: «полная архитектурная документация (4 ADR, реестр операций,
  клиентские сценарии, референсы API) осталась в источнике… и не
  транскрибирована построчно». Это мультиклиентский продукт — изменения
  затрагивают всех подключённых клиентов одновременно, не только заказчика
  конкретной задачи. Формально ближайший кандидат по критерию ADR 0003
  (наличие контракта), но без перенесённой документации доступа и операций
  задачу по нему сформулировать нечем.
- **`services/chatium/`** внешние интеграции (GetCourse SDK, AmoCRM OAuth2,
  Notion, Toggl Track v9, Bizon365 API v2.0, `cloud-tech-tasks/services/chatium/overview.md`
  §«Возможности», блок E01–E06) — исполняются в облаке Chatium, не нашей
  системой; это не кандидаты в задачи CITA, а перечень интеграций чужой
  платформы. Раздел «Доступ» у самой карточки Chatium — тот же TODO, что и у
  gateway. Упомянуты здесь только потому, что allocation.md §2.6 явно
  причисляет карточку `chatium` к «материалу для первых интеграций CITA»,
  не разделяя платформенные интеграции и продукт gateway; это разграничение
  ADR фиксирует явно (см. «Решение»).
- **Bizon365 API v2.0** (как один из интеграций Chatium, а не как продукт
  автора) — отдельно от вопроса пригодности карточка `services/bizon365/`
  фиксирует факт, не связанный с наличием контракта: узел, где будет работать
  CITA, физически не может достичь `start.bizon365.ru` — TLS-рукопожатие
  обрывается после ClientHello, фильтрация по SNI на нашей стороне сети,
  воспроизведена на двух разных внешних IP и подтверждена тестами против
  посторонних серверов (Cloudflare, Kinescope), диагностика заняла три раунда
  переписки с провайдером Beget, снята не была (`notes/2026-08/2026-08-08-bizon365-sni-blocked.md`,
  зафиксировано 2026-08-08). Даже если у Bizon365 найдётся пригодный контракт,
  задачу по нему с этого узла выполнить нельзя независимо от решения о первой
  интеграции.
- **Notion API** — упомянут в карточке `clients/neso/services/notion/overview.md`
  как факт существования публичного API у сервиса, но «ключ доступа не сохранён
  нигде»; раздел «Возможности и типовые операции» — «не задокументировано»,
  «Грабли» — «нет данных» (`completeness: stub`). Это не кандидат с
  недостающей документацией, а полное отсутствие материала: нет секрета, нет
  наблюдённых операций, нет ничего, что можно было бы формализовать как
  контракт CITA.

## Решение

Настоящий ADR фиксирует, что перечень первых интеграций CITA **не выбран**,
и оставляет CONTOURS.md §13 в этой части открытым — без права какого-либо
последующего документа CITA (spec.md, README, другие ADR) молчаливо
представлять один из перечисленных кандидатов как выбранный. Выбор первой
интеграции — решение, требующее либо пользователя, либо главного архитектора
работы; ни один агент, наполняющий воркспейс `vds-kz-cita`, таким полномочием
не наделён.

Фиксируется список кандидатов с их фактическим статусом на дату этого ADR,
без ранжирования по приоритету и без назначения ни одного из них:

| Кандидат | Тип | Что мешает выбрать его сейчас |
|---|---|---|
| `services/gc-chatium-gateway/` | собственный продукт (GetCourse API, старый/новый) | доступ и операции не перенесены из источника (TODO), мультиклиентский риск |
| Интеграции `services/chatium/` (GetCourse SDK, AmoCRM OAuth2, Notion, Toggl v9, Bizon365 v2.0) | интеграции чужой платформы | исполняются в облаке Chatium, не нашей системой — не задачи CITA как таковые |
| Bizon365 API v2.0 | внешний сервис | хост недостижим с узла (SNI-фильтрация), независимо от пригодности контракта |
| Notion API | внешний сервис | ключ доступа не сохранён нигде, операции не наблюдались вообще |

Отдельно фиксируется терминологическая точность: `chatium` и
`gc-chatium-gateway` — разные объекты. `chatium` описывает интеграции,
исполняемые платформой Chatium в её собственном облаке; `gc-chatium-gateway`
— собственный продукт автора, работающий поверх этой платформы. Только
второй может стать задачей CITA; первый — справочный материал о чужой
системе, не источник задач для нашего исполнителя.

## Последствия

**Положительные**

- Открытый вопрос CONTOURS.md §13 не закрывается молча и не подменяется
  произвольным выбором агента, наполняющего воркспейс; решение остаётся у
  того, кому принадлежит по правилам документооборота.
- Зафиксирован honest snapshot того, что реально известно о кандидатах — без
  этого следующая попытка выбора начиналась бы с нуля, заново перечитывая
  четыре карточки MITA.
- Явно разведены `chatium` (платформенные интеграции) и `gc-chatium-gateway`
  (продукт автора) — устраняет риск, что кто-то прочитает allocation.md §2.6
  буквально и решит, будто GetCourse SDK/AmoCRM/Notion/Toggl/Bizon365 внутри
  Chatium сами по себе — задачи CITA.

**Отрицательные / что становится дороже**

- CITA не имеет ни одной работающей задачи и не может её получить, пока
  вопрос не решён — spec.md контура вынужден описывать целевое устройство
  (реестр интеграций, схемы операций, идемпотентность) без единого реального
  примера, на котором это устройство можно проверить.
- Наиболее вероятный кандидат (`gc-chatium-gateway`) требует не только выбора,
  но и предварительной работы вне CITA — переноса раздела «Доступ» и полной
  архитектурной документации из исходного Obsidian-vault, что не относится к
  полномочиям CITA и не может быть сделано этим контуром самостоятельно.
- Bizon365 как класс кандидатов заблокирован сетевым фактом, не зависящим от
  архитектурного решения; если провайдер не снимет фильтрацию, часть
  кандидатов из таблицы выше остаётся недостижимой независимо от выбора.

## Рассмотренные альтернативы

- **Назначить `gc-chatium-gateway` первой интеграцией явным решением этого
  ADR**, раз он и так назван «ближайшим реальным кандидатом» в ADR 0003.
  Отклонена: «ближайший кандидат» — оценка расстояния до готовности, а не
  решение о выборе; раздел «Доступ» не заполнен, полная документация операций
  не перенесена, задачу сформулировать не из чего. Назначение интеграции без
  этого материала было бы решением, принятым за пользователя или архитектора
  работы, что запрещено разделом «Задача» этого ADR и общими правилами
  документооборота.
- **Считать перечисление интеграций `services/chatium/` (GetCourse SDK,
  AmoCRM, Notion, Toggl, Bizon365 v2.0) готовым списком кандидатов CITA**,
  раз они явно названы в источнике. Отклонена: это интеграции, которые
  исполняет облако Chatium, а не наша система; у CITA нет к ним прямого
  доступа и точки входа — задачи там нет и не появится, пока не изменится
  архитектура самой платформы Chatium.
- **Оставить вопрос вообще без ADR**, поскольку CONTOURS.md §13 уже фиксирует
  его как открытый на уровне проектных документов. Отклонена: правила
  документооборота требуют, чтобы у контура CITA было явное, датированное
  решение об отсутствии выбора со списком кандидатов и причин — иначе при
  повторном обращении к вопросу придётся заново поднимать четыре карточки
  MITA и notes/ для восстановления того же контекста.

## Условия пересмотра

- Пользователь или главный архитектор работы явно называет первую интеграцию
  CITA — тогда этот ADR не редактируется, а помечается закрытым со ссылкой на
  новый ADR, фиксирующий выбор.
- Раздел «Доступ» и архитектурная документация `services/gc-chatium-gateway/`
  переносятся из исходного Obsidian-vault в MITA — снимает как минимум одно
  из препятствий у самого вероятного кандидата и требует обновить таблицу.
- Провайдер (Beget) снимает SNI-фильтрацию `start.bizon365.ru`, либо принято
  архитектурное решение об исходящем прокси/туннеле для этого хоста —
  снимает сетевое препятствие у Bizon365 как класса кандидатов.
- Появляется общее решение по критерию «пригодности» контракта (условие
  пересмотра ADR 0007) — может изменить состав таблицы кандидатов, если под
  него подойдут наблюдённые эндпоинты Kinescope или Bizon365.

## Источник

Решение не перенесено из принятого источника: CONTOURS.md §13 называет
«перечень исходных интеграций CITA и целевых систем MITA» открытым вопросом,
и ни один пункт `second-system/DECISIONS.md` (D-001…D-012) его не закрывает.
Материал по кандидатам — `allocation.md` §2.6 (таблица «Данные CITA») и карточки
`cloud-tech-tasks/services/gc-chatium-gateway/overview.md`,
`cloud-tech-tasks/services/chatium/overview.md`,
`cloud-tech-tasks/services/bizon365/overview.md`,
`cloud-tech-tasks/notes/2026-08/2026-08-08-bizon365-sni-blocked.md`,
`cloud-tech-tasks/clients/neso/services/notion/overview.md`. Статус — «Отложено»,
поскольку это не решение о выборе, а явная фиксация его отсутствия; повышать
статус до «принято» или «предложено» некорректно — ничего не предлагается и
не принимается, кроме признания того, что вопрос остаётся открытым.
