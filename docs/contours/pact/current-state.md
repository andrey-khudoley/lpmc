## 1. Инвентаризация: чего нет

В каталоге `/home/agent/workspaces/vds-kz-pact` нет ничего, кроме файлов документации,
перечисленных в `docs/README.md` (`docs/spec/spec.md`, `docs/adr/`, `docs/README.md`,
`docs/overview.md`, этот файл, а также `egress-today.md`, `secrets-today.md`,
`inherited-from-mita.md`, `open-questions.md`, `sources.md`). Ни одного
исполняемого компонента PACT не существует нигде — ни здесь, ни в остальных трёх
воркспейсах, ни в `cloud-tech-tasks`:

- **Кода нет.** Ни диспетчера (LLM-классификатор задачи/capabilities), ни
  enforcement-слоя (детерминированная проверка полномочий) не написано ни строки.
- **Реестра задач с полномочиями нет.** Задачи существуют только как файлы карточек
  внутри MITA (см. §2 ниже); централизованной выдачи разрешений на задачу — нет.
- **Таблиц правил и capabilities нет.** Нет ни одной структуры данных, которая
  сопоставляла бы «класс задачи → необходимые полномочия».
- **Классификации необратимых операций и решений approval нет.** Нет ни списка
  необратимых действий, ни механизма запроса подтверждения.
- **Журнала вердиктов нет.** Ни одной записи вида «задаче X выдано полномочие Y» не
  существует ни в каком формате.
- **Egress-проверки результата нет.** Ничто не проверяет текст, который MITA готовит
  для человека, перед тем как он покинет привилегированный контур.
- **Единой точки между недоверенным и привилегированным контуром нет.** Пользователь
  сегодня отдаёт команды напрямую агенту MITA в сессии Claude Code / Codex CLI —
  никакого посредника на этом пути нет физически.
- **Слово «PACT» не встречается ни разу в исходниках MITA** — ни в `AGENTS.md`
  (собранном из `.agents/policy/`), ни в самих файлах `.agents/policy/`
  (`common/00-purpose.md` … `common/13-agent-toolkit.md`, `runtime/claude.md`,
  `runtime/codex.md`), ни во всех 44 журналах `llm/` (34 в корневом системном `llm/`
  + 10 владельческих: `clients/neso/llm` — 3, `clients/larina/llm` — 6,
  `internal/llm` — 1; см. `vds-kz-mita/docs/llm-journals.md` §7). То же верно
  для «LINA» и «CITA».
- **Egress-контроль на уровне сети тоже отсутствует.** Роль `nftables`
  (`/var/lib/infra/src`) фильтрует только `INPUT`; цепочка `OUTPUT` — `policy accept`.
  Факт подтверждён диагностикой блокировки Bizon365 08.08.2026. Исполнитель MITA имеет
  прямой исходящий сетевой доступ без какого-либо посредника.

Единственный механизм детерминированного enforcement, который в системе физически
есть, — `.githooks/pre-commit`. Он проверяет не то, что делает PACT: только
целостность канона агентского тулинга (`lint`/`check` над `.agents/`, т.е. что
`.claude/`, `.codex/agents/*.toml`, `.codex/mcp-servers.toml` и корневые
`AGENTS.md`/`AGENTS.override.md` соответствуют сгенерированному плану). К
безопасности исполнения задач клиента, к выдаче полномочий или к egress-проверке
результата этот хук отношения не имеет.

Ниже — не архитектурное решение, а перечень носителей, которые сегодня физически
закрывают то, что по архитектуре должно принадлежать PACT. Все пути — внутри
репозитория `/home/agent/workspaces/cloud-tech-tasks`, если не указано иное.

## 3. Оговорка: сопоставление «сущность MITA ↔ контур» — реконструкция, не факт

Важно не смешивать два разных утверждения:

- **Факт из источников:** слово «PACT» (как и «LINA», «CITA») не встречается ни в
  одном файле `cloud-tech-tasks` — ни в `AGENTS.md`, ни в `AGENTS.override.md`, ни в
  `.agents/policy/`, ни во всех 44 журналах `llm/` (34 в корневом системном `llm/` +
  10 владельческих). MITA описывает саму себя как
  самодостаточную систему: «файлы + git — единственный источник истины», без какого-
  либо упоминания внешнего арбитра.
- **Реконструкция, не факт:** всё сопоставление в таблице §2 («вот это в MITA сегодня
  закрывает вот эту функцию PACT») построено задним числом, применением определения
  PACT из постановки задачи пользователя к уже существующим файлам и правилам MITA.
  Это инженерная гипотеза о происхождении и месте будущего PACT, а не описание того,
  что сама MITA считает собой сделанным «за PACT». В частности, в MITA нет ни одного
  документа, который называл бы своё правило «временной заменой PACT» или ссылался на
  четырёхконтурную модель как на целевую архитектуру для себя.

Три артефакта в MITA по смыслу ближе всего к «черновому ТЗ на PACT», сформулированному
самой системой заранее, но и они не называют PACT по имени:

1. `notes/2026-08/2026-08-05-prompt-injection-threat-model.md`, раздел «Меры», пп. 1–3, 5
   — вход в сервисы без показа секрета агенту, разделение ролей по доверию, allowlist
   исходящих соединений, гейты на необратимые действия.
2. `ROADMAP.md`, этап 2 — предусловие «изоляция и контроль исходящего — до включения
   Telegram и cron».
3. `.agents/ARCHITECTURE.md`, инвариант 7 — «семантика безопасности не может зависеть
   от метаданных, которые клиент игнорирует».
