# Документация участка PACT: индекс

## Статус контура

**PACT как работающая система не реализован.** Рабочего кода, реестра задач, таблиц
правил, capabilities, журнала вердиктов и egress-проверки результата в этом
воркспейсе (`/home/agent/workspaces/vds-kz-pact`) нет. Каталог содержит только
документацию: желаемое состояние (`docs/spec/spec.md`), архитектурные решения
(`docs/adr/`), этот индекс и файлы текущего состояния (`overview.md`,
`current-state.md`, `secrets-today.md`, `egress-today.md`, `inherited-from-mita.md`,
`open-questions.md`, `sources.md`). Ни один файл каталога не является исполняемым
компонентом.

Функции, которые по архитектуре принадлежат PACT (реестр задач и состояний, таблицы
правил, реестр владельцев как канонический справочник скоупа политик, custody
секретов, классификация необратимых операций, approval, egress-проверка), сегодня
физически исполняет сама MITA и её носители в репозитории
`/home/agent/workspaces/cloud-tech-tasks` — без какого-либо посредника. Egress-контроля
на узле нет вообще: цепочка `OUTPUT` в роли `nftables` — `policy accept`. Подробности
разнесения см. в `/home/agent/workspaces/cloud-vds-admin/second-system/` (CONTOURS.md,
SPECIFICATION.md, DECISIONS.md) и в исследовании
`/tmp/vds-kz-pipeline/research/allocation.md`, которое обосновывало текущее разбиение
на воркспейсы — оба источника внешние по отношению к этому каталогу и здесь не
дублируются. Единственное исключение — `docs/secrets-today.md`: фактическое
описание того, где сегодня физически лежат секреты MITA и как ими пользуется
исполнитель, без единого значения.

## Три вида файлов в `docs/` и их назначение

- **`docs/*.md` (кроме `spec/` и `adr/`)** — «docs-as-state»: текущее фактическое
  состояние участка PACT. Пишется только в прошедшем и настоящем времени, без
  конструкций «будет», «планируется». Не имеет права ссылаться на `spec.md` за
  данными — исключение сделано только для принципиально неизменных вещей
  (расшифровка имени контура PACT и его место в общей четырёхконтурной схеме).
  Помимо `README.md`, в этом разделе есть `overview.md` (расшифровка имени и место в
  схеме), `secrets-today.md` (где сегодня физически лежат секреты MITA),
  `egress-today.md` (контроль исходящего трафика: egress-контроля нет, `OUTPUT` —
  `policy accept`), `inherited-from-mita.md` (конвенции и артефакты MITA, которые по
  смыслу переходят в зону PACT, но пока не унаследованы), `current-state.md`
  (рабочая инвентаризация: чего нет и кто сегодня фактически исполняет функции,
  назначенные PACT) и `sources.md` (карта первоисточников и их статусы: где физически
  лежат материалы, определяющие контур, и известные ловушки этих материалов).
- **`docs/spec/spec.md`** — «spec-as-source»: желаемое состояние, опережающее
  воркспейс. Один файл, полная спецификация участка PACT: назначение, инварианты,
  реестр задач, модель полномочий, custody секретов, egress-политика, событийные
  контракты, критерии приёмки, открытые вопросы. Каждое заимствованное положение
  сопровождается ссылкой на источник (`CONTOURS.md §`, `SPECIFICATION.md §`, `D-xxx`,
  `REVIEW-FINDINGS §`). Имеет право описывать то, чего в каталоге ещё нет.
- **`docs/adr/`** — архитектурные решения, один файл = одно решение, нумерация
  `NNNN-kebab-case.md` сквозная внутри контура PACT. Каждый файл несёт свой
  **реальный** статус (Принято / Предложено / Отложено), а не желаемый; для решений,
  перенесённых из `second-system/DECISIONS.md`, указан исходный идентификатор D-xxx
  и статус в источнике на момент переноса.
